# MetaAutomate — Open-Source-First Roadmap

**Principle:** make the core reproducible, trustworthy and useful to contributors before trying to scale it as a hosted platform.

These milestones are proposals, not release announcements.

## Phase 1 — Open-source planning foundation (current priority)

- Publish accurate docs and feature-status matrix.
- Preserve the existing GPLv2 license pending deliberate license/provenance review.
- Deliver a one-command isolated local contributor demo and reliable end-to-end testing.
- Add contribution rules, code of conduct, private disclosure policy, CI and a maintainer review process.
- Expand accessibility, observability and deterministic work-graph planning.

**Acceptance:** a newcomer can clone, run, create/save/review a draft objective and shut down the demo without touching the maintainer's environment.

## Phase 2 — Trusted community ecosystem

- Modularize domain capability definitions, review schemas and safe extension boundaries.
- Expose stable, versioned contracts for capability metadata and proposed tasks.
- Document plugin/adapter interfaces **without enabling real tool execution**.
- Establish regular releases, changelog, review ownership, issue labels and developer documentation.
- Collect community feedback and research use cases in agriculture, healthcare, food security, business operations and other sectors.

## Phase 3 — Production security and pilot readiness

- Make identity-provider integrations and account lifecycle verifiable.
- Harden database tenant isolation against arbitrary runtime SQL and separate privileged administration.
- Add rate limiting, abuse controls, encrypted backups, restore tests, vulnerability management and operating procedures.
- Run real OIDC/browser security testing with authorized identities before any customer-facing pilot.
- Review legal rights for contributed code and official brand assets.

**Acceptance:** signed-off threat model, negative security tests, private pilot runbook and demonstrated recovery.

## Phase 4 — Controlled private deployment

- Pilot with a limited group and consent-based access.
- Prove observability, authorized organization data separation, rollback and incident response.
- Measure meaningful user outcomes rather than VM count or inflated capabilities.
- Keep infrastructure expenses and access changes subject to explicit approval.

## Phase 5 — Authorized, verifiable execution

- Introduce only independently reviewed capabilities that have real contracts, permissions and verification.
- Separate planning approval from each category of external action permission.
- Maintain audit logs, idempotency, user cancellation, least privilege, fail-closed behavior and evidence of outcomes.
- Scale adoption based on demonstrated value, safe operations and sustainable governance.

**Long-term vision:** a global, impact-driven MetaAutomate ecosystem. Strategic aspirations are not present-tense capabilities.
