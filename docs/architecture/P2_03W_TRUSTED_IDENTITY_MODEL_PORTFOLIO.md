## Build order, delivered source increments

1. **Canonical Intelligence architecture** — retain existing P2-03o 12-module Business Intelligence Lab and its 5 shared engines. `synthetic_governed_intelligence_portfolio.py` now loads the **actual existing Python module outputs** for Academy and Bespoke demo tenants; verifies all module names and order; checks accounting that modeled contribution = gross sales - identified costs and confirms that continuity models reconcile. Maps every module to the engine(s) it uses, a relevant model evaluation test category, a strictly virtual per-module tool allowlist and privacy/identity/measurement gates.
2. **Separately signed mock OIDC evidence** — `synthetic_oidc_identity.py` accepts only offline-generated, signed Ed25519 JWTs with pinned `kid`, `alg=EdDSA`, exact issuer/audience, no unknown JSON fields, canonical base64url, bounded expiration/authentication freshness, sample `pwd` + `mfa` flags, independently maintained demo tenant/role membership, and simulated key/token revocation. The verified identity is then cross-checked with the independent existing app-signed role token. This is **test evidence, not actual OIDC login, independent employee ID verification or live MFA**.
3. **Two-person approval and controlled tools** — the P2-03v durable review state machine must verify the same fictional owner and separate reviewer before any internal simulation. `GovernedIntelligenceGateway` checks both identity layers *on each operation*. A tool is accepted only for an allowlisted **module + tool + purpose**, and the underlying signed security reviewer must match the persisted approval. All results are a **virtual review receipt**, never tool execution.
4. **Model evaluation architecture** — `synthetic_model_evaluation.py` references provider-documented model identifiers (`gpt-6-astra`, `gpt-6.1-sol`, `gpt-6-luna`, `claude-opus-5-5`). It validates a structured rubric for representative cost, continuity, security and consent/publishing tasks. Responses are **prewritten test tags**, not generated by providers. The scorecard deliberately has **no live model ranking, measured cost or latency, observed accuracy, API usage or real model selection**.
5. **Evidence and continuity** — every module and engine output has an inspectable source SHA-256; fictional finance and continuity reconcile; audit and backup/restore continue to be tested in the preceding disposable milestone. Neither hashes nor staged tests imply real financial improvement or tamper-proof external audit.
6. **CI and adversarial verification** — separate identity/tool-policy and 12-module/model jobs, forged JWT header/signatures, wrong audience/tenant/role, missing MFA, stale sessions, key/token revocation, double-signature mismatch, unknown/forbidden model fixture claims, arbitrary tools, altered baselines, cross-tenant denial, and inherited P2-03u/v source-only regressions.

### Five shared engines

**Measurement:** factual/reconciled synthetic state. **Decision:** explicit hypothetical arithmetic. **Recommendation:** ranked evidence gaps and required human decisions. **Automation:** human-review state only; zero dispatch. **Learning:** descriptive period comparisons, without causal or financial impact claims.

## Critical production NO-GO limitations

Mock JWKS are CI-generated and not retrieved from a production IdP; memberships are static fictional records, not HR/SSO grants. The demo `mfa` token claim does not establish real MFA. Token/revoked-key stores are test-memory policies, not production distributed revocation. The adapter is read-only plus **fictional tool-review receipts**, not a live agent runtime. The existing persistent approval rehearsal uses a disposable SQLite database, not a real private Postgres staging service. There is no external trusted audit anchor, independently validated identity, complete recovery assurance, permitted customer data or autonomous external tools.

Before live operation: separate private-staging cost/network approval, real SSO/OIDC+MFA+JWKS rotation, verified tenant memberships, full audit and RPO/RTO testing, key/secrets management, PII minimization and retention, source provenance, provider platform authorization and explicit end-to-end GO decisions.
